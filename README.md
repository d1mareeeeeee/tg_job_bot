# tg_job_bot — подбор вакансий из Telegram по резюме через LLM

Бот читает новые посты из публичных Telegram-каналов с вакансиями, отсеивает
не-вакансии, оценивает остальные через LLM на соответствие вашему резюме (0–100)
и присылает подходящие вам в личку через отдельного бота-уведомителя. Работает по
расписанию и не обрабатывает один пост дважды. **Api-ключ Telegram не нужен.**

## Возможности

- 📡 Чтение каналов **без api-ключа Telegram** — через публичное веб-превью `t.me/s/`.
- 🧮 Оценка каждой вакансии через **LLM** (OpenAI / Anthropic / Gemini / OpenRouter)
  по вашему резюме, с баллом 0–100 и кратким обоснованием.
- 🚫 **Жёсткое правило:** гибридные и очные вакансии получают score 0 (если нужна
  только удалёнка).
- 💸 Работает на **бесплатных** моделях OpenRouter (со страховкой «только бесплатные»).
- 🔔 Уведомления в личку через **бота-уведомителя** (Telegram Bot API).
- 🗃️ **Дедупликация** через SQLite — один пост не обрабатывается дважды.
- ⏱️ Работа **по расписанию** с настраиваемым интервалом опроса.

## Как это работает

1. **Веб-парсер** читает публичное веб-превью каналов `https://t.me/s/<username>`
   (обычный HTTP, без авторизации и без api_id/api_hash).
2. **Префильтр** по ключевым словам отбрасывает явные не-вакансии (экономия токенов).
3. **LLM** оценивает соответствие вакансии вашему резюме (0–100).
4. **Бот-уведомитель** присылает подходящие вакансии (score ≥ порога) вам в личку.
5. **SQLite** хранит обработанные посты и отправленные совпадения.

> **Ограничение:** читаются только **публичные** каналы с включённым веб-превью.
> Приватные каналы и инвайт-ссылки (`t.me/+...`, `joinchat/...`) так читать нельзя —
> они пропускаются с предупреждением в логе.

## Требования

- Python 3.11+
- Аккаунт Telegram (для бота-уведомителя) и ключ LLM (проще всего — бесплатный
  OpenRouter).

## Установка

```bash
cd tg_job_bot
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Конфигурация

Вся конфигурация — в файле `.env`. Ключ Telegram (`api_id`/`api_hash`) не нужен.

### Шаг 0. Создайте файл `.env` из шаблона

```bash
cp .env.example .env
```

Формат строк — `ИМЯ=значение`, **без кавычек и без пробелов** вокруг `=`. Строки,
начинающиеся с `#`, — комментарии.

### Шаг 1. `CHANNELS` — какие каналы отслеживать

Список **публичных** Telegram-каналов через запятую (`@username`, `username` или
ссылка `https://t.me/username`):

```
CHANNELS=@examplejobs,@remotework,https://t.me/somechannel
```

> Проверить, читается ли канал: откройте в браузере `https://t.me/s/имя_канала`
> (напр. <https://t.me/s/durov>). Есть лента постов — подойдёт; пусто — канал
> приватный или без веб-превью, бот его не прочитает.

### Шаг 2. `NOTIFY_BOT_TOKEN` — бот, который будет писать вам

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`.
2. Задайте имя и username бота (username должен заканчиваться на `bot`).
3. Вставьте выданный токен:
   ```
   NOTIFY_BOT_TOKEN=1234567890:AAExxxxxxxxxxxxxxxxxxxx
   ```
4. **Обязательно** нажмите **Start** (`/start`) в чате со своим ботом — иначе он
   не сможет написать вам первым.

### Шаг 3. `NOTIFY_CHAT_ID` — куда слать (ваш Telegram-аккаунт)

Числовой id вашего аккаунта — узнайте у [@userinfobot](https://t.me/userinfobot):

```
NOTIFY_CHAT_ID=123456789
```

### Шаг 4. Подключение LLM

LLM сравнивает вакансию с вашим резюме. Проще всего и бесплатно — через OpenRouter.

**Вариант А (рекомендуется): OpenRouter, бесплатная модель**

1. Зарегистрируйтесь на <https://openrouter.ai> → раздел **Keys** → создайте ключ
   вида `sk-or-v1-...`.
2. Выберите бесплатную модель на <https://openrouter.ai/models?max_price=0>
   (у бесплатных id заканчивается на `:free`).
3. Заполните в `.env`:
   ```
   LLM_PROVIDER=openai
   LLM_API_KEY=sk-or-v1-ваш_ключ
   LLM_BASE_URL=https://openrouter.ai/api/v1
   LLM_MODEL=inclusionai/ling-3.0-flash:free
   LLM_JSON_MODE=false
   LLM_REQUIRE_FREE=true
   ```
   - `LLM_JSON_MODE=false` — многие бесплатные модели не поддерживают строгий JSON.
   - `LLM_REQUIRE_FREE=true` — если случайно указана платная модель, запуск падает
     с ошибкой (цена проверяется через OpenRouter).

**Вариант Б: обычные OpenAI / Anthropic / Gemini (платно)**

```
LLM_PROVIDER=openai        # или anthropic, или gemini
LLM_API_KEY=sk-...ваш_ключ
LLM_MODEL=gpt-4o-mini      # модель провайдера
```
Ключи: [OpenAI](https://platform.openai.com/api-keys) ·
[Anthropic](https://console.anthropic.com/) ·
[Gemini](https://aistudio.google.com/app/apikey).
`LLM_BASE_URL` оставьте пустым, `LLM_REQUIRE_FREE=false`.

> `LLM_MODEL` **обязателен** — если оставить пустым, программа завершится с ошибкой.

### Шаг 5. Резюме / критерии оценки

Критерии оценки берутся из текстового файла (по умолчанию `resume.txt`). В
репозитории лежат только шаблоны — создайте свой файл из шаблона:

```bash
cp resume.txt.example resume.txt        # точный поиск по вашим навыкам
# или широкий поиск по направлениям/позициям:
cp positions.txt.example positions.txt
```

Впишите резюме в свободной форме (роль, навыки, опыт, желаемый формат). Чем
подробнее — тем точнее оценка. Какой файл использовать — задаётся `RESUME_PATH`
(по умолчанию `resume.txt`); для широкого поиска укажите `RESUME_PATH=positions.txt`.

### Остальные переменные (можно оставить по умолчанию)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MATCH_THRESHOLD` | `70` | Минимальная оценка (0–100), при которой вакансия присылается. Ниже — больше вакансий, выше — только самые подходящие. |
| `POLL_INTERVAL_MINUTES` | `30` | Как часто (в минутах) проверять каналы. |
| `LOOKBACK_MESSAGES` | `50` | Сколько последних постов проверять в каждом канале за цикл. |
| `FIRST_RUN_SILENT` | `false` | `true` = первый проход «тихий» (то же, что флаг `--init`). |
| `LLM_RATE_DELAY` | `1.0` | Пауза (сек) между запросами к LLM — чтобы не ловить лимиты. |
| `NOTIFY_RATE_DELAY` | `1.0` | Пауза (сек) между отправками уведомлений. |
| `HTTP_TIMEOUT` | `20.0` | Таймаут запроса к t.me, секунды. |
| `HTTP_USER_AGENT` | пусто | User-Agent для запросов; пусто = дефолт браузера. |
| `RESUME_PATH` | `resume.txt` | Файл с резюме (критериями оценки). |
| `DB_PATH` | `job_bot.sqlite3` | Файл базы обработанных постов. |
| `LOG_PATH` | `job_bot.log` | Файл логов. |

**Минимально необходимый набор:** `CHANNELS`, `NOTIFY_BOT_TOKEN`, `NOTIFY_CHAT_ID`,
`LLM_API_KEY`, `LLM_MODEL` (и `LLM_BASE_URL` для OpenRouter).

## Запуск

Все команды — из папки проекта, одной строкой. Интерпретатор берём из venv.

**Шаг 1. Первый запуск — тихий** (обязательно первым). Помечает текущие старые
посты как обработанные, ничего не отправляя, — чтобы не получить сразу все старые
вакансии.

```bash
cd tg_job_bot
.venv/bin/python main.py --init
```

**Шаг 2. Обычный запуск** (постоянная работа по расписанию):

```bash
cd tg_job_bot
.venv/bin/python main.py
```

Если venv активирован (`source .venv/bin/activate`, в начале строки виден
`(.venv)`), можно короче — `python main.py`.

> ⚠️ Вводите команду **целиком одной строкой**. Если запустить только
> `.venv/bin/python` (без `main.py`), откроется интерактивный Python (`>>>`) — это
> не запуск бота; выйдите из него командой `exit()`.

Пока бот работает, терминал «занят» и выводит логи. Остановка — `Ctrl+C`.

```
tg_job_bot/
├── .env.example          # шаблон конфигурации
├── resume.txt.example    # шаблон резюме (точный поиск)

├── requirements.txt
├── README.md

├── db.py                 # SQLite: seen_posts, matches

├── llm_client.py         # абстракция LLM + промпт оценки

```

> в репозитории лежат только `*.example`.

## Логи

Пишутся в консоль и в файл `LOG_PATH` (по умолчанию `job_bot.log`). В конце
каждого цикла — статистика: проверено / прошло префильтр / оценено / отправлено.

## Устранение неполадок

- **Бот не пишет в личку** — не нажали **Start** у бота-уведомителя, либо неверный
  `NOTIFY_CHAT_ID`.
- **`Не заданы обязательные переменные окружения: ...`** — не заполнено одно из
  обязательных полей (в т.ч. `LLM_MODEL`). Смотрите список в сообщении об ошибке.
- **Все вакансии получают оценку 0 / `parse_error`** — модель не поддерживает
  строгий JSON. Поставьте `LLM_JSON_MODE=false`.
- **`Модель ... платная` при запуске** — включён `LLM_REQUIRE_FREE=true`, а модель
  не бесплатна. Выберите модель с суффиксом `:free` или снимите проверку.
- **Ошибки `429` / rate-limit** — у бесплатных моделей OpenRouter есть суточный
  лимит. Увеличьте `LLM_RATE_DELAY`, уменьшите `LOOKBACK_MESSAGES` или пополните
  баланс OpenRouter.
- **Канал не читается** — приватный, без веб-превью или неверный username. Такие
  каналы логируются и пропускаются, остальные обрабатываются.
- **Приходят старые вакансии при первом старте** — запустите один раз с `--init`.
