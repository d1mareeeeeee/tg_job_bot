# tg_job_bot — подбор вакансий из Telegram по резюме через LLM

Бот читает новые посты из публичных Telegram-каналов с вакансиями, оценивает их
через LLM на соответствие вашему резюме (0–100) и присылает подходящие в личку.
Работает по расписанию, один пост дважды не обрабатывает.

**Api-ключ Telegram не нужен** — каналы читаются через публичное веб-превью `t.me/s/`.

## Возможности

- 📡 Чтение каналов без api_id/api_hash — обычный HTTP к `t.me/s/`.
- 🧮 Оценка вакансии через LLM (OpenAI / Anthropic / Gemini / OpenRouter) с баллом
  0–100 и кратким обоснованием.
- 🏠 Ориентирован на удалёнку: вакансии, где возможен только гибрид или офис,
  получают оценку 0 (правило зашито в промпт — правится в `llm_client.py`).
- 💸 Работает на бесплатных моделях OpenRouter, со проверкой на «только бесплатные».
- 🔔 Уведомления в личку через отдельного бота (Telegram Bot API).
- 🗃️ Дедупликация через SQLite — один пост не обрабатывается дважды.
- 🛟 Сбой LLM не теряет пост: он вернётся в следующем цикле, а об ошибке бот напишет.

## Как это работает

1. Веб-парсер читает `https://t.me/s/<username>` — без авторизации.
2. Префильтр отбрасывает явный мусор (рекламу, резюме кандидатов) до вызова LLM.
3. LLM оценивает соответствие вакансии вашему резюме.
4. Вакансии с оценкой выше порога уходят вам в личку.
5. SQLite хранит обработанные посты и отправленные совпадения.

> **Ограничение:** читаются только публичные каналы с веб-превью. Приватные каналы
> и инвайт-ссылки (`t.me/+…`, `joinchat/…`) пропускаются с предупреждением в логе.

### Требования к сети

Машина, где работает бот, должна иметь доступ к трём адресам:

| Адрес | Зачем |
|---|---|
| `t.me` | чтение постов из каналов (веб-превью) |
| `api.telegram.org` | отправка уведомлений через бота |
| адрес LLM (напр. `openrouter.ai`) | оценка вакансий |

**Если Telegram у вашего провайдера заблокирован — VPN должен быть включён всё время
работы бота**, а не только в момент запуска. При выключенном VPN бот не падает: он
пишет в лог сетевые ошибки и каждый цикл возвращает `проверено=0`. Если не прочитан
ни один канал, бот один раз напишет об этом в личку и один раз — когда чтение
восстановится (обычно блокируется именно `t.me`, а `api.telegram.org` работает, так
что сообщение доходит). Ошибки по отдельным каналам в личку не отправляются — шумно,
они только в логе.

Пока доступа нет, каналы уходят вперёд: посты, вышедшие за пределы окна
`STARTUP_LOOKBACK_MESSAGES`, будут пропущены — как и при обычном простое бота.
Само окно на время недоступности остаётся широким и сузится только после цикла,
который реально прочитал каналы. Проверить доступ проще всего в браузере на той же
машине: `https://t.me/s/` плюс имя канала должно открывать ленту постов.

## Установка

Нужен [Python 3.11+](https://www.python.org/downloads/).

```bash
# macOS / Linux
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

```bat
:: Windows
py -m venv .venv-win
.venv-win\Scripts\pip install -r requirements.txt
```

Можно пропустить: скрипты `run.sh` / `run.bat` создают окружение сами при первом
запуске.

## Конфигурация

Вся конфигурация — в файле `.env`:

```bash
cp .env.example .env
```

### Обязательные переменные

**`CHANNELS`** — публичные каналы через запятую (`@username`, `username` или ссылка):

```
CHANNELS=@examplejobs,@remotework,https://t.me/somechannel
```

Проверить канал можно, открыв `https://t.me/s/имя_канала` в браузере: есть лента
постов — подойдёт, пусто — бот его не прочитает.

**`NOTIFY_BOT_TOKEN`** — токен бота-уведомителя от [@BotFather](https://t.me/BotFather)
(`/newbot`). После создания **нажмите Start в чате со своим ботом**, иначе он не
сможет написать вам первым.

**`NOTIFY_CHAT_ID`** — числовой id вашего аккаунта, узнать у
[@userinfobot](https://t.me/userinfobot).

**LLM** — проще всего бесплатно через OpenRouter: зарегистрируйтесь на
<https://openrouter.ai>, создайте ключ и выберите модель с суффиксом `:free` на
<https://openrouter.ai/models?max_price=0>.

```
LLM_PROVIDER=openai
LLM_API_KEY=sk-or-v1-ваш_ключ
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=провайдер/модель:free
LLM_JSON_MODE=false      # многие бесплатные модели не поддерживают строгий JSON
LLM_REQUIRE_FREE=true    # падать при старте, если модель окажется платной
```

Для обычных OpenAI / Anthropic / Gemini укажите `LLM_PROVIDER`, `LLM_API_KEY` и
`LLM_MODEL`, а `LLM_BASE_URL` оставьте пустым. `LLM_MODEL` обязателен всегда.

**Резюме** — критерии оценки берутся из текстового файла:

```bash
cp resume.txt.example resume.txt          # точный поиск по навыкам
cp positions.txt.example positions.txt    # широкий поиск по направлениям
```

Впишите резюме в свободной форме — роль, навыки, опыт, желаемый формат работы. Чем
подробнее, тем точнее оценка. Какой файл использовать, задаёт `RESUME_PATH`.

### Персонализация: не только `.env`

Часть настроек «под себя» живёт в коде, а не в конфигурации. Главное — **промпт оценки**
`PROMPT_TEMPLATE` в [llm_client.py](llm_client.py):

> Бот по умолчанию заточен на **полную удалёнку**. Вакансии с гибридом или офисом
> получают `score=0` жёстким правилом в промпте, а не порогом, — то есть не приходят
> никогда, сколько ни опускай `MATCH_THRESHOLD`. **Ищете работу в офисе или гибрид —
> удалите это правило из `PROMPT_TEMPLATE`**, иначе подходящих вакансий не будет вовсе.

Там же задано всё остальное поведение оценки: шкала 0–100, учёт грейда
(junior/middle/senior), разбор постов-подборок (оценка по самой подходящей позиции) и
язык ответа — промпт русскоязычный, `reason` приходит по-русски.

Полная карта мест, которые правят под себя:

| Что настраивается | Где | Когда править |
|---|---|---|
| Резюме, навыки, желаемый формат работы | `resume.txt` / `positions.txt` (выбор — `RESUME_PATH`) | всегда |
| Каналы, порог, модель, интервалы опроса | `.env` | всегда |
| Правила оценки: жёсткое правило про удалёнку, шкала, грейд, разбор подборок, язык | `PROMPT_TEMPLATE` в [llm_client.py](llm_client.py) | ищете офис/гибрид; нужна другая логика оценки |
| Стоп-слова мусора: реклама, инфоцыганство, резюме кандидатов | `STRONG_MARKERS` / `SPAM_MARKERS` / `AD_MARKERS` / `RESUME_RE` в [prefilter.py](prefilter.py) | другой язык постов или другая сфера — списки русскоязычные и настроены на IT/DS-каналы |
| Формат уведомления (`Оценка: N/100` + текст вакансии + ссылка) | `_build_message` в [notifier.py](notifier.py) | хочется другой вид сообщения |

Личные ограничения (нежелательные направления, грейд, стоп-темы) добавляйте в
`resume.txt` / `positions.txt`, а **не** в префильтр: пост часто содержит сразу
несколько вакансий, и префильтр отсеял бы его целиком вместе с подходящей.

### Остальные переменные

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MATCH_THRESHOLD` | `70` | Минимальная оценка, при которой вакансия присылается. |
| `POLL_INTERVAL_MINUTES` | `30` | Как часто проверять каналы. |
| `LOOKBACK_MESSAGES` | `50` | Сколько последних постов проверять в канале за цикл. |
| `STARTUP_LOOKBACK_MESSAGES` | `100` | Окно первого цикла после запуска — чтобы не потерять посты, вышедшие за время простоя. |
| `FIRST_RUN_SILENT` | `false` | `true` = тихий первый проход (то же, что `--init`). |
| `LLM_RATE_DELAY` | `1.0` | Пауза между запросами к LLM, сек. |
| `NOTIFY_RATE_DELAY` | `1.0` | Пауза между отправками уведомлений, сек. |
| `LLM_FAILURE_STREAK` | `3` | Сколько сбоев LLM подряд считать «провайдер лежит». |
| `LLM_BACKOFF_MINUTES` | `30` | Пауза после такой серии сбоев. |
| `HTTP_TIMEOUT` | `20.0` | Таймаут запроса к t.me, сек. |
| `HTTP_USER_AGENT` | пусто | User-Agent; пусто = дефолт. |
| `RESUME_PATH` | `resume.txt` | Файл с критериями оценки. |
| `DB_PATH` | `job_bot.sqlite3` | База обработанных постов. |
| `LOG_PATH` | `job_bot.log` | Файл логов. |

За полноту отвечает `LOOKBACK_MESSAGES`, а не частота опроса: за цикл бот видит
только это число свежих постов, и если канал успел опубликовать больше, лишние
теряются безвозвратно. Каналы-агрегаторы часто постят пачками по 10–15 штук, поэтому
при интервале 5–10 минут разумный минимум — 20, при интервале от получаса — 30–50.
На расход токенов ни одна из этих переменных не влияет: обработанные посты повторно
не оцениваются. Подробнее — в комментариях `.env.example`.

Если бот работает не круглосуточно, за ночь или выходные постов может выйти больше,
чем помещается в обычное окно. Поэтому первый цикл после запуска смотрит канал шире —
на `STARTUP_LOOKBACK_MESSAGES` постов, — а со второго возвращается к обычному окну.
Расширение платится один раз за запуск, так что значение можно брать с запасом.

## Запуск

Первый запуск делайте с `--init`: он пометит текущие посты обработанными, ничего не
отправляя, чтобы не получить разом все старые вакансии.

```bash
./run.sh --init      # macOS/Linux (один раз: chmod +x run.sh)
./run.sh
```

```bat
run.bat --init       :: Windows
run.bat
```

Или напрямую интерпретатором из окружения:

```bash
.venv/bin/python main.py --init        # macOS/Linux
.venv-win\Scripts\python main.py       # Windows
```

Бот работает в фоне терминала и пишет логи. Остановка — `Ctrl+C`.

## Структура проекта

```
tg_job_bot/
├── main.py               # оркестрация + планировщик
├── config.py             # чтение и валидация .env
├── telegram_reader.py    # веб-парсер t.me/s/
├── prefilter.py          # отсев явного мусора перед вызовом LLM
├── llm_client.py         # абстракция LLM + промпт оценки
├── notifier.py           # уведомления через Bot API
├── db.py                 # SQLite: seen_posts, matches
├── run.sh / run.bat      # запуск с автосозданием окружения
├── *.example             # шаблоны .env, резюме и профиля позиций
└── dev_tests/            # ручные проверки логики, для работы бота не нужны
```

Реальные `.env`, `resume.txt` и `positions.txt` не коммитятся — в репозитории лежат
только шаблоны `*.example`.

## Логи

Пишутся в консоль и в файл `LOG_PATH` (по умолчанию `job_bot.log`). В конце каждого
цикла — статистика: проверено / прошло префильтр / оценено / отправлено.

Судьба каждого поста видна отдельной строкой — это единственный способ узнать,
почему вакансия не пришла: в базу (`matches`) попадают только прошедшие порог,
остальные оценки нигде не сохраняются.

```
Оценка 5 (порог 50): https://t.me/examplejobs/123 — DevOps инженер | Вне направлений ML/DS
Префильтр отсеял https://t.me/examplejobs/124: Розыгрыш! Подпишитесь на канал и получите…
```

> Токен бота в логах маскируется. Но при неожиданных сбоях туда попадает трассировка
> с абсолютными путями вашей машины — просмотрите файл, прежде чем прикладывать его
> к issue.

## Устранение неполадок

- **Бот не пишет в личку** — не нажали Start у бота-уведомителя либо неверный
  `NOTIFY_CHAT_ID`.
- **`Не заданы обязательные переменные окружения`** — не заполнено обязательное поле,
  список в тексте ошибки.
- **`Модель … платная` при запуске** — включён `LLM_REQUIRE_FREE=true`. Выберите
  модель с суффиксом `:free` или снимите проверку.
- **Много сообщений «⚠️ ОШИБКА ПАРСИНГА»** — модель отвечает не JSON. Поставьте
  `LLM_JSON_MODE=false` или смените модель. Вакансия при этом не теряется —
  приходит без оценки.
- **Ошибки `429`** — лимиты бесплатной модели. У OpenRouter их два: суточный и
  **20 запросов в минуту**. Второй легко поймать на пачке постов: `LLM_RATE_DELAY=1.0`
  даёт 60 запросов в минуту, то есть втрое больше лимита. Ставьте 3.0 и выше.
  Посты при этом не теряются: они не помечаются обработанными и вернутся в следующем
  цикле, а после `LLM_FAILURE_STREAK` сбоев подряд бот уйдёт в паузу на
  `LLM_BACKOFF_MINUTES`.
- **Канал не читается** — приватный, без веб-превью или неверный username.
- **`Сетевая ошибка при чтении канала …` сразу на всех каналах** — с машины нет
  доступа к `t.me`. Чаще всего выключен VPN (Telegram заблокирован у провайдера) или
  запросы режет файрвол/антивирус. Бот пишет об этом отдельной строкой в логе и
  продолжает попытки каждый цикл — достаточно включить VPN, перезапуск не нужен.
  Тот же корень бывает у `403` в предупреждении о проверке платности модели: без VPN
  не открывается и `openrouter.ai`.
- **Ничего не приходит, хотя вакансии в каналах есть** — если вы ищете офис или гибрид,
  сработало жёсткое правило про полную удалёнку в `PROMPT_TEMPLATE`
  ([llm_client.py](llm_client.py)): такие вакансии получают `score=0`. Уберите правило
  из промпта. См. «[Персонализация: не только `.env`](#персонализация-не-только-env)».
- **Приходят старые вакансии при первом старте** — запустите один раз с `--init`.
