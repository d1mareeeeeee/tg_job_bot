# dev_tests — ручные проверки бота

Не pytest, а два самостоятельных скрипта: запускаются напрямую, печатают
`[OK ]` / `[FAIL]` по каждой проверке и в конце общий итог. Запускать **из корня
проекта** интерпретатором из venv (путь к корню скрипты определяют сами):

```powershell
.venv-win\Scripts\python.exe dev_tests\test_seen_logic.py
```

## `test_seen_logic.py` — основной, безопасный

39 проверок логики `main.run_cycle` и `main.main_loop` на заглушках: подменяются
reader, LLM, `send_match` и `send_error`, база — временный файл.
**Сеть не используется, реальные сообщения не отправляются, боевая БД не трогается.**

Что покрыто:

1. `LLMCallError` — посты не помечаются `seen`, серия из 3 сбоев прерывает цикл;
2. те же посты возвращаются в обработку, когда LLM ожила;
3. `LLMParseError` — пост закрывается, уходит с пометкой мимо порога, пишется в `matches`;
4. низкий скор и не-вакансии закрываются молча;
5. `--init` (`first_run_silent`) не трогает LLM;
6. чередование сбоев и успехов: серия не растёт, не больше 3 сообщений об ошибке за цикл;
7. дедупликация падений цикла — гоняется **настоящий** `main_loop` с подменённым
   `run_cycle`.

## `test_live_error.py` — шлёт реальные сообщения

Проверяет, что уведомления об ошибках действительно доходят в Telegram: берёт
настоящие `NOTIFY_BOT_TOKEN`/`NOTIFY_CHAT_ID` из `.env`, но LLM всегда заглушка —
квота провайдера не тратится. База временная, боевая не затрагивается.

**Без флагов не шлёт ничего** — печатает подсказку и выходит.

| Флаг | Сообщений | Что проверяет |
|---|---|---|
| `--call` | 3 | `LLMCallError`: эскалация «Попытка 1 из 3» → «3 из 3» + «Пауза 30 мин». Посты не помечаются seen |
| `--parse` | 1 | `LLMParseError`: вакансия уходит с шапкой «⚠️ ОШИБКА ПАРСИНГА» мимо порога (порог поднят до 100) |
| `--crash` | 2 | Падение цикла в настоящем `main_loop` + дедупликация: 3 одинаковых падения → 1 сообщение, другое → ещё 1 |
| `--all` | 6 | Все три сценария подряд |

```powershell
.venv-win\Scripts\python.exe dev_tests\test_live_error.py --all
```

В `--crash` интервал ускорен до нуля, поэтому в сообщении будет «через 0 мин» —
в боевом режиме там реальный `POLL_INTERVAL_MINUTES`. Все тестовые ошибки помечены
`[ТЕСТ, не настоящая ошибка]`, чтобы их нельзя было спутать с боевыми.
